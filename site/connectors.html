Connectors

Harness / CI covers postgres, mysql, mongodb, and rest. Everything else ships in the binary without Compose goldens — test against your own instance.

Stable

type Pushdown Notes
postgres stable filter, project, agg, groupBy, order, limit, same-source join sslMode; statementTimeoutMs
mysql stable same as postgres
mongodb stable filter, project, agg, groupBy, order, limit same-source join via DuckDB
rest stable eq filter, project, limit/offset options.resources required; aggs in DuckDB

Experimental

type Pushdown Notes
mssql exp same as postgres encrypt
sqlite exp same as postgres pathEnv; binding.schema: main
clickhouse exp same as postgres native port typically 9000
dynamodb exp key equality, project, limit pk/sk accessPath or UNSUPPORTED
cassandra exp partition equality, project, limit accessPath.partition required
ksql exp key equality, project, limit pull only; ksqlKey required
redis exp key equality, project, limit GET/HGETALL/LRANGE/… only; never KEYS/delete
kafka exp partition+offset / key / time no consumer group; never produces
graphql exp eq → variables, project, optional limit graphql_operation; query-only documents

Limits that matter

  • Not sources Oracle, BigQuery, Snowflake, Elasticsearch, S3-as-table are out of the matrix. Many JSON APIs are already rest (+ from-openapi).
  • Access path DynamoDB, Cassandra, ksql, Redis, and Kafka need the documented key/partition equalities or return UNSUPPORTED.
  • Read-only streams Redis/Kafka never mutate keys, offsets, or topics (decision D19).
  • graphql source Documents must be query-only; mutations are rejected before any HTTP call. Agents still call Query IR / catalog SQL (decision D17).
